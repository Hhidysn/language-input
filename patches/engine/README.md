`output/` (build artifacts committed into the fork: `output/model-host/**` DLLs,
`LanguageInputModelHost.exe`, `output/install.nsi`, `output/model-host.manifest.json`;
83 added + 1 modified tracked files, ≈102 MB of binaries). These are **not** first-party source and
are regenerated by the build. The series was generated with an exclude pathspec:

```
git -C F:\documents\software\languageInput format-patch 0.17.4..a57d7f0 \
  -o patches\engine --no-signature --binary -- . ':(exclude)output'
```

The three commits that touch `output/` are still captured in full for their
source changes; only their binary build outputs are omitted. If a byte-exact
`output/` cache is ever needed, regenerate it by building; do not re-add it here.

**Not captured — untracked in the fork working tree:**

reproduces the committed range `0.17.4..a57d7f0` byte-exactly; uncommitted
files are out of scope by construction. Salvage that file separately if it is
still wanted.

## 3. Submodules store a URL + a commit — not content

**A git submodule records only a repository URL and a commit SHA. It does not
contain any file content.** Consequences:

* If we pointed a submodule at `Hhidysn/weasel` and that fork is deleted, the
  submodule URL breaks and a fresh `git submodule update` would fail forever.
  This is why we submodule **official `rime/weasel`** and keep our changes as
  plain patches in this repo (patches are content, committed here, and survive
  any fork deletion).
* The nested `librime`/`plum` are submodules of *the engine*, resolved through
  the engine's own `.gitmodules` (official `rime` URLs) — again, no fork URL.
* `librime-sensitive-mode.patch` is applied to the nested `engine/librime`
  checkout (see `tools/build-engine.ps1`); it is **not** part of the numbered
  series that applies to the engine root.

## 4. Reproduction

Prerequisites: git, and (for an actual build) the toolchain in `PINS.md §4`.
Network access to GitHub is required once, to clone `rime/weasel` and its nested
submodules.

```powershell
# from the repo root: F:\documents\software\langInput

# 1. Add official rime/weasel as a submodule at engine\ pinned to 0.17.4.
#    Idempotent; prints every command. Add -DryRun to only preview.
.\tools\add-engine-submodule.ps1

# 2. Apply patches\engine\*.patch to engine\, init nested submodules, and build.
#    Fails loudly if Visual Studio / xmake / CMake / Boost are missing.
.\tools\build-engine.ps1 -DryRun      # preview
.\tools\build-engine.ps1              # real build

# 3. Full product orchestration skeleton (engine -> model host -> settings app).
.\tools\build-all.ps1 -DryRun
```

Manual equivalent of step 2's patch application (for auditing):

```powershell
# run from the repo root; use absolute patch paths (git -C engine resolves
# relative arguments against engine\)
$repo = (Get-Location).Path
git -C engine submodule update --init --recursive
Get-ChildItem "$repo\patches\engine\*.patch" | Where-Object Name -match '^\d{4}-' |
  Sort-Object Name | ForEach-Object { git -C engine apply --whitespace=nowarn $_.FullName }
# the librime patch targets the nested submodule, not the engine root:
git -C engine\librime apply --whitespace=nowarn "$repo\patches\engine\librime-sensitive-mode.patch"
```

> The exact, correct commands are implemented in `tools/build-engine.ps1`; use
> that script rather than the sketch above.
